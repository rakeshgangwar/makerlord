# design-sync notes — MakerLord

- This repo is a Svelte 5 APP, not a React component library: no dist/
  components, no Storybook; nearly all UI lives in
  packages/ui/src/routes/+page.svelte. The sync is **identity-only**
  (off-script layout): tokens + styles.css + guidelines, a stub
  _ds_bundle.js (window.MakerLord = {}), no component cards, no
  _ds_sync.json anchor (next sync re-verifies everything — correct).
- Token source of truth: packages/ui/src/routes/+layout.svelte `:root`.
  If those tokens change, regenerate ds-bundle/tokens/bench-tokens.css.
- Fonts come from Google Fonts (see packages/ui/src/app.html), not repo
  files — styles.css @imports the same URL; no fonts/ dir shipped.
- Future path if the UI is ever componentized (StageRail, FindingStrip,
  MeterStrip, Dock, SvgViewer…): a React bridge that mounts the compiled
  Svelte components is feasible (Svelte 5 mount() in an effect; callback
  props map well, slots don't). Revisit then; not worth it for one
  component today.
- 2026-07-29 (second sync): the componentization landed, so the sync now
  ships 11 REAL components — compiled Svelte 5 in React wrappers
  (window.MakerLord.*), built by scripts/build-ds-bridge.mjs; cards/d.ts/
  prompt.md generated by scripts/gen-ds-cards.mjs with real engine-shaped
  sample props. Components carry optional props with store fallback (that
  refactor is in the app repo). InspectView deliberately excluded: it
  fetches live /render projections and would show empty canvases.
- Verification via Chrome CDP, not the validator's playwright path
  (validator run with --no-render-check): 11/11 DOM assertions + composite
  visual grade; the identity styles.css folds the body::before wash into
  the background stack (the app keeps its .frame z-index approach).
- The bundle stubs $app/environment (browser=true); the app store guards
  localStorage for sandboxed iframes. React 18 UMD vendored for cards.
- No _ds_sync.json anchor (off-script layout) — every sync re-verifies.
