# MakerLord Simulation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build stage ⑤ — SPICE netlist projection from the project model, `.op`/`.tran`/`.ac` with provenance-bounded findings (D43), the stimulus model, the convergence ladder that never lies, requirement discharge, and four new registry tools (32 → 36).

**Architecture:** One package, `@makerlord/sim`, depending on parts/circuit/project (not on tools — the four `sim_*` ToolDefs live in `@makerlord/tools` and call into it, avoiding a cycle). Every pipeline step is a projection or a parse; nothing is generated by a language model.

**Tech Stack:** TypeScript (strict), Node 22, pnpm, Vitest. ngspice invoked as a subprocess in the integration layer only.

**Spec:** [../specs/2026-07-29-simulation-design.md](../specs/2026-07-29-simulation-design.md)

## Global Constraints

- **D43: a run's provenance is the weakest model in the loop.** `verified`/`computed` → BLOCKER ceiling; `sourced` → WARNING; `assumed` → NOTE. One idealised part caps the whole analysis.
- **The MCU boundary:** digital parts become behavioural stubs (supply-current sink + declared drive), `assumed` unless curated. We simulate the analogue envelope, never the firmware.
- **A run that did not converge produced no result — not a pass.** `SIM_NO_CONVERGENCE` is a NOTE about the *simulation*, never about the circuit; the ladder rungs tried are recorded.
- **An assumed stimulus caps the run at NOTE** (`SIM_STIMULUS_ASSUMED`), exactly like an idealised model.
- **Not-simulable requirements are named, never silently skipped.**
- **`predict_dc` is untouched.** The gate must never depend on numerical luck.
- **No ngspice in unit tests.** Golden netlist files + canned parser fixtures; the integration layer skips **loudly** when the binary is missing.
- **CSV is canonical.** (PNG derivation deferred — needs a plot renderer; named below.)

## File Structure

```
packages/sim/src/
├── provenance.ts    ModelProvenance, weakest(), severityCeiling(), cap()
├── models.ts        part → SPICE card + provenance; MCU stub; curated .lib lookup
├── stimulus.ts      Stimulus type + SPICE source projection
├── netlist.ts       circuit + models + stimuli → circuit.cir (golden-file tested)
├── parse.ts         ngspice op/wrdata output parsers
├── findings.ts      SIM_* checks over parsed results
├── ladder.ts        convergence retry ladder (options per rung)
├── run.ts           ngspice subprocess runner + artifacts (integration only)
├── discharge.ts     requirement → analysis mapping; explicit not-simulable
└── index.ts
data/spice/          curated .lib models, keyed by partId (verified provenance)
```

### Task 1: Provenance model (the executable D43)

- [ ] `ModelProvenance = 'verified' | 'computed' | 'sourced' | 'assumed'`; `weakest()`; `severityCeiling()`; `capFinding()`
- [ ] Tests: ceilings per D43's table; weakest-not-average

### Task 2: Device models

- [ ] Resistor from profile `resistanceOhms` → `computed`; LED from profile `forwardVoltageV` → diode card, `computed`; curated `data/spice/<partId>.lib` → `verified`; MCU (has `pinMaxMa`) → behavioural stub, `assumed`; nothing → stub + `SIM_MODEL_MISSING`
- [ ] Tests incl. the missing-model fixture: part named, run capped at NOTE

### Task 3: Stimulus

- [ ] `Stimulus` per spec §5 with provenance + rationale; projection to `V`/`I` SPICE sources (`dc`, `pulse`, `pwl`, `sine`, `load_step`)
- [ ] `SIM_STIMULUS_ASSUMED` NOTE listing every assumed stimulus with rationale
- [ ] Tests: derived/stated/assumed carry weight; assumed caps at NOTE

### Task 4: Netlist projection

- [ ] Intent-net connectivity → node map (gnd-role pin net = node 0); readable, hand-runnable `circuit.cir` with a provenance comment per device
- [ ] Golden-file tests: fixture project in, exact `.cir` out (deterministic projection, D2 — equality is the right assertion)

### Task 5: Parsers and findings

- [ ] `parse.ts`: `.op` `name = value` output; `wrdata` column output for `.tran`/`.ac`
- [ ] `findings.ts`: `SIM_ABSMAX_EXCEEDED`, `SIM_POWER_DISSIPATION`, `SIM_RAIL_SAG` (min over window vs part minimum), `SIM_AC_CORNER_MISMATCH` (−3 dB corner vs numeric requirement), all capped by run provenance
- [ ] Tests over canned ngspice output: known-answer arithmetic (divider ratio, RC corner within 2% of 1/(2πRC), one-τ charge ≈ 63.2%)

### Task 6: Ladder, runner, discharge

- [ ] `ladder.ts`: default → gmin stepping → source stepping → relaxed tolerances → gear → give up; each successful rung recorded in the result; results at relaxed tolerance labelled as the weaker claim
- [ ] `run.ts`: ngspice `-b` subprocess, `sim/` artifacts (`circuit.cir`, `results/*.csv`, `report.md`); missing binary throws a clear error
- [ ] `discharge.ts`: metric → analysis table; **explicit `not-simulable`** verdicts; verdict severity obeys D43
- [ ] Integration tests `describe.skipIf(noNgspice)` — skip prints a loud warning naming the install command
- [ ] Tests: convergence-failure fixture (no circuit findings, nothing passed, rungs listed); discharge fixture pair (checkable vs not)

### Task 7: The four tools, 32 → 36

- [ ] `sim_stimulus_set`, `sim_run`, `sim_results` (progressive disclosure — summary + run id, traces fetched on demand, downsampled), `sim_check_requirements` — none gated
- [ ] Registry invariants updated: 36 tools, gated set unchanged; CLI + MCP grow them for free
