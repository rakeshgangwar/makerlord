# MakerLord UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `packages/ui` per the UI spec — the framework-agnostic UI core (finding surface, postures, event consumer, renderers, bench/gate state, concurrency and bridge states) fully tested, plus the SvelteKit shell that assembles it. The spec's own three-way split (shell+Converse / Inspect+renderers / Bench+gate) becomes phases A–C of this plan.

**Architecture:** The load-bearing logic is **not framework-shaped** (spec §12) and lives in `src/lib` as pure TypeScript over the typed model — renderers are deterministic SVG projections of `project.json` (D2), the finding surface is a store that only engine data can write, selection is model-level. Svelte components are thin assemblies over that core.

**Tech Stack:** SvelteKit (D41), TypeScript (strict), Vitest. three.js and Playwright deferred (named below).

**Spec:** [../specs/2026-07-29-ui-design.md](../specs/2026-07-29-ui-design.md)

## Resolved before planning (spec §1 ⚠️)

The spec flagged a contradiction: it assumed Web Serial is Chromium-only while
references.md recorded Firefox support. **Verified 2026-07-29: Firefox 151
(May 2026) shipped Web Serial** ([Mozilla Hacks announcement](https://hacks.mozilla.org/2026/05/web-serial-support-in-firefox/));
only Safari lacks it. references.md was right. **The bridge is a minority
fallback** — §11's prompt table triggers on Safari, BYO agents, and local
clones, not on Firefox.

## Global Constraints

- **Findings are rendered from engine data, never agent prose.** The strip is fed by `ToolResult` payloads carried verbatim in `SessionEvent` and by the UI's own `check_*` calls. **No API on the finding surface can dismiss, hide or downrank** — the DOM-level analogue of the registry invariant.
- **A BLOCKER is never off-screen**: the strip collapses to a severity summary, never to nothing.
- **Severity is never colour alone** — icon + label + colour, always.
- **Provenance badge matches the severity ceiling** (`verified`/`computed` → BLOCKER, `sourced` → WARNING, `inferred`/`assumed` → NOTE).
- **Four postures, not seventeen modes:** Converse ①②③④⑯ / Inspect ⑤⑨⑩ / Bench ⑥⑦⑧⑬ / Decide ⑪⑫⑭⑮⑰.
- **Measurement entry takes a number, never a checkbox; the predicted value is not shown until after entry** (D15).
- **`STALE_PROJECT` renders as a specific, non-alarming reload state.** Never force-push; "pull first".
- **Renderers are deterministic projections** — golden SVG equality, not perceptual diffs.
- **Degradation is explicit:** bridge-absent controls carry their reason.

## File Structure

```
packages/ui/src/lib/
├── postures.ts          stage → posture map, region priority per breakpoint
├── findings.ts          FindingSurface store — engine-fed, undismissable
├── severity.ts          icon + label + colour triples; provenance badges
├── events.ts            the ONE SessionEvent consumer (SSE and WS feed it)
├── stale.ts             STALE_PROJECT and diverged-tree states
├── bridge.ts            §11 prompt table (Safari fallback) + absent reasons
├── selection.ts         model-level selection, view-agnostic
├── bench.ts             step state, gate preflight machine, wake-lock intent
└── renderers/
    ├── breadboard.ts    hole-accurate SVG from the grid + placements + wires
    ├── blocks.ts        block diagram SVG from the architecture facet
    ├── schematic.ts     shared layout engine (D27) + SVG projection
    └── waveform.ts      CSV trace → path points (canvas draws them)
packages/ui/src/routes/  SvelteKit shell: three-region frame + strip
```

- [ ] `postures.ts` with the §5 mapping and §4 breakpoint collapse rules (strip never collapses)

- [ ] Tests: posture map; BLOCKER visible at every breakpoint; no dismiss API (introspection sweep); provenance/ceiling consistency; prose-cannot-remove; stale is non-alarming

### Phase B — Inspect and the renderers

- [ ] `renderers/breadboard.ts`: hole-accurate SVG from `HoleGrid` + placements + wires — golden equality test
- [ ] `renderers/blocks.ts`: architecture → block diagram SVG — golden
- [ ] `renderers/schematic.ts`: the shared layout engine (grid placement + orthogonal nets), exported separately from the SVG projection so the KiCad generator (D27) can consume the same layout — golden
- [ ] `renderers/waveform.ts`: trace → normalised path points, downsampling-aware
- [ ] `selection.ts`: selecting `R3` is a model event; every renderer marks it — linkage inherited by construction
- [ ] Tests: golden SVGs byte-wise; selection linkage across renderers

### Phase C — Bench and the gate

- [ ] `bench.ts`: one-step state (others dimmed, not hidden); measurement entry accepts numbers only; **prediction revealed only after entry**; pass/fail against tolerance; wake-lock intent while a build is live; steering is a first-class action
- [ ] Gate moment: preflight-shaped state machine — instruction, one number, visible consequence
- [ ] Tests: predicted-value hidden until entry; checkbox-shaped input impossible; gate cannot pass without a recorded number

**Deferred, named:** Playwright end-to-end (browser download; the no-LLM golden path is covered at the tool layer), three.js GLB viewer (stage ⑩ arrives with the mechanical stage), live SSE/WS server wiring (needs the hosted deployment; both transports already converge on `events.ts`), svelte-check in CI, bridge packaging (its own spec per §15).
