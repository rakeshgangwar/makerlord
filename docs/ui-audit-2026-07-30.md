# MakerLord UI Audit — 2026-07-30

*Full end-to-end pass of the deployed UI, audited against a world-class
bar: every page, every posture, desktop + mobile, plus code-level
checks (a11y tree, contrast, network behaviour, fonts). Method: the
real stack served locally with the seeded golden + danger projects,
driven through Chrome DevTools; findings referenced to source.
Provenance: every claim below was observed, not guessed.*

**Verdict.** The product's soul is right and already visible: the
workbench identity (solder-mask green, engineering-grid mat, resistor
colour-coded phases, the instrument strip), safety choreography that
reads like a bench manual, and honest copy that no template product
would write ("a print claiming 'all good' proves nothing"). But there
is one **P0 correctness defect** (a reactive fetch storm that kills
the flagship stage on refresh/deep-link), a layer of **engine
vocabulary leaking raw into maker-facing surfaces**, and a set of
composition and craft gaps that keep it at "strong prototype", not
"world class product". Grades by area:

| Area | Grade | One line |
|---|---|---|
| Identity / design language | **B+** | Real point of view; diluted at the edges (login/join, links, cards) |
| Correctness under navigation | **F** | Bench/simulate deep-link = infinite request storm; blank flagship stage |
| Vocabulary & copy | **B−** | Superb voice where hand-written; raw net/part/corpus IDs where generated |
| Layout & composition | **C+** | ≥50% dead space on most stage views at 1440px; unscaled schematic |
| Mobile | **C−** | Chip-cloud rail eats the first screen; hero below the fold; stretched phase bars |
| Accessibility | **B−** | Labeled landmarks, alt text, reduced-motion — but no h1, no skip link, two contrast fails, static tab title |
| Craft details | **B−** | Entity bug, default-blue links, wordmark inconsistency, port-field noise |

## 1. P0 — the bench eats itself on refresh (fix before anything else)

**Symptom.** Any cold load whose lens is bench or simulate —
refreshing the Prototype stage, opening a shared
`/?p=…&stage=6` link — fires `/steps` + breadboard + schematic SVG
renders in an unthrottled loop with an incrementing `?t=N`
cache-buster. Observed: **3,907 requests in under a minute**, then
`net::ERR_INSUFFICIENT_RESOURCES` (Chrome refuses further fetches),
a starved tab, and the flagship stage rendering **blank**: "No build
steps yet", empty board, empty schematic, artifact panel claiming "No
project on the bench". The SPA click-path is unaffected — which is
exactly why the e2e suite (click-path + fast assertions) never caught
it.

**Mechanism.** `packages/ui/src/routes/+page.svelte:63-67` — the
deploy-restart retry effect:

```js
$effect(() => {
  if ((lens === 'bench' || lens === 'simulate') && app.projectId && !app.build) {
    refreshProjections();
  }
});
```

`refreshProjections()` (`app.svelte.js:277`) begins with
`app.renderTick += 1` — a **read-modify-write of reactive state inside
the effect's tracking context**. The effect therefore subscribes to
`renderTick`, and every run schedules the next: a self-sustaining loop
that floods the fetch queue faster than responses can land, so
`app.build` never sticks and the guard never turns it off.

**Fix shape.** `untrack(() => refreshProjections())` plus an
in-flight/once guard (retry belongs to boot with backoff, not an
unconditional effect). Add a regression e2e: **reload the bench URL**
and assert build steps render AND total request count stays sane.
Server-side, the storm also means each stray tab hammers the engine
with full SVG renders — worth a `Cache-Control` or ETag on `/render/*`
regardless.

## 2. P0-adjacent engine leak — entity-encoded part titles

"**220 &#8486; Resistor**" renders literally (front door "To
acquire", library, anywhere a title flows). The Fritzing `.fzp` title
carries the XML numeric entity for Ω and the parts ETL never decodes
it — verified live in the `inventory_gap` payload, so it is
engine-side (`packages/parts` ETL), poisoning every consumer including
CLI and agent prose. Decode numeric + named entities at import time;
add a corpus test asserting no `&#` survives in any curated title.

## 3. The identity is real — finish it

What already works (protect these): the two-tone wordmark; the
engineering-grid mat; resistor-colour phase bars on the rail; the
dark instrument strip with the lamp dot (`READY · no open findings` /
`1 finding · 1 blocking`); stage eyebrows ("⑥ … blocks first, parts
later"); the build-step choreography opening on POWER OFF with the
justification *"Everything that follows happens on a dead board"*;
the danger strip pairing cause with remedy **and the resistor math**;
honest disclaimers on serial output. This is a product with a thesis:
**the bench is an instrument, not a chat window.**

Where it dilutes:

- **/login and /join have none of it.** Plain white card, flat
  "MakerLord" (not even the two-tone mark), generic centering. The
  front door of an invite-only product is the one place a visitor
  decides what this is. Bring the bench: the grid, the mark, the
  meter strip idle at the bottom, the stage vocabulary.
- **Default-blue underlined links** on /join ("Sign in") — off-palette
  browser default inside an otherwise tokenized system.
- **Flat grey part chips** in the library with no affordance and no
  tier colour; SOURCED is badged but VERIFIED (the thing the whole
  curation pipeline exists to celebrate) is invisible.
- Findings-strip red, phase colours, meter glow are all good tokens —
  but nothing in the UI ever uses `--copper` except the stage eyebrow,
  which is also one of the two contrast failures (below). Decide what
  copper means (suggest: provenance/measured-value accents) or drop it.

## 4. Vocabulary leakage — the engine talks to makers in its own IDs

The best copy in the product is hand-written; the worst is generated.
A world-class bar means the projection layer translates every internal
name before it reaches a maker's eyes:

- **Debug stage headline** renders
  `Voltage at net_INDICATOR2_cathode__INDICATOR3_Pin 0` in display
  type, followed by a wall of machine-joined hypothesis text. The
  engine knows this net is "LED cathode → resistor junction"; say
  that. The hypothesis explainer needs sentence-level generation, not
  string-joined net lists.
- **Build steps** say *'Run the signal wire for net "A98"'* — a hole
  ID promoted to a net name in maker-facing instructions (the very
  thing D-series decisions forbid inferring meaning from). Steps
  should name parts and pins ("run the wire from LED1's anode to
  D5"), never bare hole IDs.
- **Library taxonomy** is raw corpus family strings with inconsistent
  casing: "cpu board (raspberry pi)", "MaxDetect Technology", and the
  absurd one-item category "Dagu DGServo 9g" containing "Dagu DGServo
  9g (End View)". Curate a display taxonomy (a small mapping file is
  enough for 23 parts; a default title-case + merge rule for the
  corpus).
- **Part IDs as display names**: inventory shows `5mmColorLEDModuleID
  ×1`, blocks show `arduino_Uno_Rev3(fix)`. Titles exist — use them,
  keep IDs to tooltips/mono metadata.
- **Truncated project id** `e2e000` (6 chars of an 7+-hex id) in the
  artifact panel and front-door cards — either the full id in mono or
  none; a truncated id is noise pretending to be information.

## 5. Layout & composition

- **Dead space dominates at 1440px+.** Architecture, Firmware, Idea:
  content hugs a ~1200px left column; the right half of the workspace
  is empty mat. Bench: steps column + two stacked panels, lower 40%
  empty. Options: a max-width centered workspace, or let panels
  breathe into a real grid (board+schematic side by side at wide
  viewports).
- **The schematic never scales.** In its panel it renders at
  intrinsic size — a stamp in a big white card (bench), unreadable at
  a glance. `SvgViewer` should fit-to-panel with zoom on demand
  (already hints "scroll to zoom" on blocks — make it uniform).
- **Stage 1 (Idea) on an open project is a void**: a lone composer
  pinned top-left, no transcript context, no guidance about what this
  stage is for. Every stage should open with its eyebrow + a one-line
  empty-state that tells the maker what talking here produces.
- **Composer alignment**: the floating dock's left edge aligns to
  nothing (not the rail, not the content column). Align it to the
  content column grid.
- **Artifact panel on the front door** shows `project.json` + "No
  project on the bench" + tabs before any project exists — machinery
  visible before it has anything to say. Hide the panel (or show a
  library teaser) until a project is open.
- The `5V ·` link label on the block diagram collides with the
  arrowhead.

## 6. Mobile (390×844)

- **The rail chip-cloud consumes the entire first screen** — 17 stage
  chips + library link + local-brain box + port field + user strip
  before any content. Mobile needs a collapsed stage indicator (current
  stage + progress) that expands on demand.
- **Phase bars stretch** on wrapped rows (16/17 show tall colour bars
  — flex stretch on the left border) — visual bug.
- **The hero is below the fold** on the front door; "What do you want
  to make?" should be the first thing a phone shows, not stage 14's
  chip.
- The findings strip stays visible and the BLOCKER reads fully —
  the most important mobile behaviour already works.
- The port field + local-brain plumbing has no business on a phone
  screen by default.

## 7. Accessibility

Working: labeled landmarks (`nav[Stages]`, `aside[Artifacts]`,
`footer[Findings]` with `aria-live="polite"`), alt text on every
image, `prefers-reduced-motion` respected, `lang="en"`, focus-visible
outline defined.

Gaps:

- **No `h1` anywhere in the app shell** — heading structure starts at
  `h3` in the artifact panel. Screen-reader navigation has no page
  anchor. The stage eyebrow is the natural h1.
- **No skip link** past the 17-button rail — a keyboard user tabs
  through every stage on every page.
- **Contrast failures (small text):** `--sev-warning #b87400` on
  `#f3e8cf` (badge-assumed, 0.62rem) ≈ 3.2:1; `--copper #b26a38`
  eyebrows on the mat ≈ 3.8:1 at 0.72rem. Both under WCAG AA 4.5:1.
  Darken both one step.
- **Touch/click targets**: rail rows 25px tall; the signed-in strip's
  "bridge token"/"sign out" are 0.66rem underline buttons — under any
  touch-target guideline.
- **Static `<title>`** ("MakerLord") — should carry project · stage
  ("desk lamp · Prototype — MakerLord") for tab identity and history.

## 8. Craft details

- **Google Fonts via CDN** — external request, FOUT on slow links, a
  privacy caveat for an EU-hosted product. Self-host the two families
  (subset woff2, ~50KB total).
- Wordmark: two-tone in the rail, flat on /login, /join, and nothing
  reflects it in the favicon/manifest (check `manifest.webmanifest`
  name/icons match the brand).
- "23 parts — verified and sourced are usable; geometry is
  browse-only" — good honest line; put the same tier legend on part
  chips themselves (colour + word, matching the severity discipline of
  icon+label+colour everywhere).
- Danger project artifact panel says "Nothing settled yet — it fills
  in as you talk" while the board shows a placed LED — the panel keys
  on requirements/blocks only; it should acknowledge circuit parts.
- The composer placeholder is "ask the agent…" on every stage; the
  stage-aware product should hint stage-appropriate asks ("describe a
  requirement…", "ask why this step matters…").

## 9. What genuinely delights (keep, and lean in)

1. The findings strip as a dark instrument panel with a lamp — the
   single best signature element; consider it the product's heartbeat
   (subtle glow shift when state changes, respecting reduced-motion).
2. Build steps that read like a mentor at your shoulder — "every
   mistake so far was made unpowered" is world-class safety copy.
3. The BLOCKER card showing its rule name + the arithmetic for the
   remedy — provenance as UI.
4. The hypotheses list where candidates die only by strikethrough
   contradiction — a truthful representation of the debug engine.
5. "how the bench greets you" as the handle placeholder.
